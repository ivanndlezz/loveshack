# Plan: Import Full Yacht Pricing Comparator into v3 + Bottom Island Menu Access

**Plan ID / Branch hint:** 1779731051565-clever-circuit  
**Date:** 2026-05-25  
**Status:** Ready for implementation (after user review)

## 1. Objectives
- Port the **complete, self-contained functionality** of `pricing-comparison.html` (the refactored Apple iOS/macOS-style Yacht Price Comparator) into the v3 single-page application architecture.
- Make the comparator accessible as a first-class screen via a new `.menu-item` inside the `.bottom-island` sheet-body (the expandable menu).
- Preserve 100% feature parity, including all recent enhancements (commission number inputs + two-way slider sync + `FORM_CONFIG` JSON for min/max/step/default).
- Maintain high visual fidelity to the post-Tailwind BEM + design tokens version while integrating cleanly with v3's design system, router, storage patterns, toasts, icons, and theming.
- Ensure the implementation is maintainable, scoped to avoid conflicts, and follows existing v3 screen patterns.

## 2. Background & Current State
- `pricing-comparison.html` is a ~2,800-line standalone HTML file containing:
  - Full simulator (cohort segmented control 2–8h, passenger/extra-hour steppers, A vs B source selectors).
  - Dynamic comparison cards + diff banner + "Copiar Reporte".
  - CRUD catalog (add/edit/delete/copy-to-all durations).
  - Import sheet with presets (Hacienda Real, Direct Base) + JSON paste + price modifier + commission.
  - Internal responsive bottom/side sheets for forms.
  - Custom BEM CSS + Apple design tokens (recently extracted after Tailwind removal).
  - Recent change: commission display converted to editable `<input type="number">` with two-way binding to the range slider, driven by `FORM_CONFIG`.
- v3 is a modular hash-router SPA (`v3/index.html` + `v3/js/app.js` + per-screen files in `v3/js/screens/` + CSS modules).
- Bottom island menu (`.bottom-island > .sheet-body > .menu-grid`) already contains several `.menu-item` buttons wired via inline script in `index.html`. "Compare" (`#menu-compare`) navigates to `#/compare`.
- v3 uses Tabler icons via SVG `<symbol>` + `<use>`, global `window.Toast`, `window.Storage`, consistent header patterns, and controlled bottom-nav visibility per screen.

## 3. Scope

### In Scope
- Full port of both main tabs: "Simular" (comparator engine) and "Tarifas" (CRUD catalog).
- All controls, calculations, dynamic rendering, sheets, import flow, copy-to-clipboard report.
- The new commission text inputs + slider sync + `FORM_CONFIG`.
- Access exclusively via a new menu item in the bottom-island sheet (label + icon).
- New route (suggested: `#/yacht-pricing`).
- New screen file + dedicated CSS.
- Proper lifecycle (`render(container, params)`, optional `destroy`).
- Icon replacement (no Lucide dependency).
- Theming (light/dark) compatibility using v3 tokens where possible.
- Hiding the main bottom island while the comparator screen is active (prevent visual conflict with its internal floating tab bar).
- Back navigation to dashboard.

### Out of Scope (for this iteration)
- Deep data integration between yacht pricing data and the main reservation system / pricing calculator.
- Cloud sync or sharing of the yacht pricing database.
- Major visual redesign to replace the custom BEM components with v3 "step-card" / sheet primitives (keep fidelity; scope instead).
- Adding the comparator as a FAB action (menu only).
- Removing or deprecating the standalone `pricing-comparison.html` (can be kept as reference or later archived).

## 4. Architecture & Key Decisions

### 4.1 Route & Naming
- **Route:** `#/yacht-pricing`
- **Screen object:** `YachtPricingScreen` exported from `v3/js/screens/yacht-pricing.js`
- **Menu label (Spanish, matching app tone):** "Comparador Yates"
- **Menu item ID:** `menu-yacht-pricing`
- **CSS file:** `v3/css/screens/yacht-pricing.css` (linked in `index.html`)
- **Optional future split:** If the JS grows too large, extract core logic to `v3/js/modules/yacht-pricing.js`, but start with a single screen file for simplicity.

### 4.2 Scoping & Conflict Avoidance (Critical)
The original comparator defines many generic classes (`.sheet`, `.toast`, `.hidden`, `.flex`, grid utilities, etc.) and uses internal sheets with the recently fixed pointer-events logic.
- Wrap the entire comparator UI in a root container: `<div class="yacht-pricing-app" id="yacht-pricing-root">...</div>`
- Prefix or scope **all** CSS rules in the new stylesheet:
  ```css
  .yacht-pricing-app .sheet { ... }
  .yacht-pricing-app .comparison-card { ... }
  /* etc. */
  ```
- Internal toasts → replace with `window.Toast.success / error` (remove the custom `#toast` element and related JS).
- Internal sheets → keep the current implementation (it works and was just fixed) but fully scoped under `.yacht-pricing-app`. Do **not** reuse global `.sheet` classes.

### 4.3 Icons
- v3 has a limited set of predefined `<symbol id="icon-...">` (house, chart, gear, etc.).
- The comparator uses ~20 Lucide icons.
- **Strategy:** During porting, replace every `data-lucide` / `<i data-lucide>` with inline `<svg viewBox="0 0 24 24">` (or `<use>` where a close match exists). This matches patterns already used in the menu items and step footer. No external Lucide script.

### 4.4 Bottom Navigation Behavior
- When the yacht pricing screen is active: `showBottomNav = false` (hide the main `.bottom-island`).
- Provide a clear "Back" or "Cerrar" affordance in the screen's own header that calls `window.App.navigate('#/dashboard')`.
- The comparator's internal floating pill bar ("Simular" / "Tarifas") remains the primary navigation inside the tool.

### 4.5 Data & Persistence
- Keep the existing `localStorage` key (`yacht_pricing_db_apple`) and `DEFAULT_PRICING_DATA` / `IMPORT_PRESETS` / `FORM_CONFIG` inside the module.
- Do **not** migrate to `window.Storage` in this port (isolation is simpler and safer).
- `FORM_CONFIG` (with commission min/max/step/default) must be preserved and used for the number inputs and clamping.

### 4.6 Theming
- The custom tokens in the comparator (Apple grays, #007AFF, etc.) map reasonably to v3 tokens (`--color-accent-blue`, surface colors, etc.).
- In the scoped CSS, prefer v3 variables (`var(--color-text)`, `var(--color-surface)`, etc.) where a close semantic match exists; fall back to the original hex values for exact Apple fidelity on cards, sheets, and accents.

### 4.7 Header Strategy
- The screen renders its own header bar inside `render()` (similar to other complex screens).
- Include a back button (left arrow) that navigates to dashboard.
- Title: "Yacht Prices" (or localized "Precios de Yates").

   - Replace all `lucide.createIcons()` calls with nothing (icons will be static inline SVGs).

## 6. Risks & Mitigations
- **CSS class collisions / global pollution** → Strict `.yacht-pricing-app` scoping + removal of generic utilities (`.flex`, `.hidden`, etc.) from global scope.
- **Icon maintenance** → Document the replacement list; prefer simple inline SVGs.
- **Sheet stacking conflicts** → Keep comparator sheets fully internal and scoped; never rely on global `.sheet` or scrim during this screen.
- **Large single file** → Acceptable for first port. Note in the file header that splitting is a possible follow-up.
- **Lucide removal** → One-time icon audit during porting.
- **User expectation of "Apple fidelity" vs v3 design** → Document that we keep the custom tokens/BEM inside the wrapper for this tool; future unification can be a separate task.
